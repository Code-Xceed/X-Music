Mod Features Overview

Designed for high performance and effortless in-game usability.

Zero FPS Drop Threading

Audio decoding and stream pre-resolution execute on background worker threads (XMusic-AudioWorker), ensuring 0ms impact on main loop FPS.

YouTube & Local Audio Engine

Stream YouTube audio via Piped API with local yt-dlp fallback. Automatically decodes MP3, OGG, AAC, and FLAC files directly to OpenAL context.

Glassmorphic Screen GUI

Exact translucent screen layout matching Minecraft standard dimensions. Parent screens are preserved so your live 3D world stays visible.

16 Version Cohort System

Built with Unimined and Manifold preprocessor directives supporting 16 distinct Minecraft releases from 1.21 to 26.2 seamlessly.

In-Game MiniPlayer HUD

View active track title, artist, and album artwork on your HUD with customizable position, transparency, and animated toast popups.

Hotkey Media Controls

Press M at any time to open the music client. Full keybinding controls for play/pause, next track, and volume slider.

TECHNICAL SPECIFICATION

1. XMusic System Architecture

XMusic is built upon a decoupled multi-module Gradle architecture. High-level audio playback state, Java audio decoders, state persistence, and glassmorphic UI components are maintained inside the platform-independent :common module, while loader mixins and keybindings reside inside :fabric.

Codebase Structure 
X-Music/
├── common/                  # Decoupled Core Audio Engine & UI Layouts
│   ├── audio/decoders/      # Jaad (AAC), JLayer (MP3), Jorbis (OGG) Decoders
│   ├── config/              # XMusicConfig State Persistence & Storage
│   ├── gui/                 # Glassmorphic Screen Components & Renderers
│   ├── lavaplayer/          # LavaPlayer Engine & Stream Resolver
│   └── player/              # PlayerFacade Unified Controller & State
└── fabric/                  # Fabric Entrypoints & Mixin Injections
    ├── mixin/               # ScreenMixin, PauseScreenMixin Injections
    └── XMusicFabric.java    # Mod Initialization & Client Event Hooks

1.2 Data Flow & Controller

The central entrypoint for all audio operations is the PlayerFacade singleton. It manages track queues, playback state transitions, background worker threads, and dynamic switching between native audio decoders and LavaPlayer streams.

1.3 Storage & Configuration Directories

All persistent state and downloaded media tools are stored inside standard Minecraft directories:

  • .minecraft/config/xmusic/xmusic.json — User settings, keybinds, volume, and overlay position.
  • .minecraft/config/xmusic/cache/ — Cached YouTube stream URLs, artwork thumbnails, and metadata.
  • .minecraft/config/xmusic/tools/ — Standalone yt-dlp and ffmpeg executables.

2. Dual-Backend Audio Pipeline

XMusic implements a dual-backend architecture to support both remote web streaming and local file playback without third-party audio drivers:

  • LavaPlayer Stream Backend: Handles YouTube audio resolution via fast Piped/Invidious REST endpoints with local yt-dlp process fallback. Streams process directly into raw PCM buffers.
  • Native File Backend: Uses standalone Java decoders (JAAD for AAC/M4A, JLayer for MP3, JOrbis/Tritonus for OGG) to pipe PCM audio directly into Minecraft's OpenAL audio context.

2.2 YouTube Stream Resolver Pipeline

To protect users against IP rate-limiting and ensure instant stream startup (~200ms), YouTube audio URLs pass through a multi-stage resolution pipeline:

  1. Memory Cache Check: If a valid stream URL is cached (TTL: 4 hours), it is returned immediately.
  2. Piped / Invidious API: Resolves stream URLs via high-speed REST queries (~200ms, zero local CPU overhead).
  3. Local yt-dlp Fallback: Executes yt-dlp with --no-cache-dir --skip-download if Piped queries fail.

2.3 Local Format Decoders

Embedded decoders shaded directly inside release mod JARs:

  • de.sfuhrm:jaad:0.8.7 (AAC / M4A Audio Decoder)
  • com.googlecode.soundlibs:jlayer:1.0.1.4 (MP3 Audio Decoder)
  • com.googlecode.soundlibs:vorbisspi:1.0.3.3 (OGG Vorbis Audio Decoder)
  • com.googlecode.soundlibs:tritonus-share:0.3.7.4 (PCM Audio Stream Share)

3. Multi-Version Unimined & Manifold Matrix

XMusic maintains complete cross-version compatibility across 16 Minecraft releases (`1.21` to `26.2`) using **Unimined** and **Manifold** conditional preprocessor definitions:

Manifold Preprocessor Code Example 
#if MC_RENDER_MATRIX_2D
    public void extractRenderState(GuiGraphicsExtractor graphics, int mouseX, int mouseY, float partialTick) {
        if (parentScreen != null) {
            try {
                parentScreen.extractRenderState(graphics, -999, -999, partialTick);
            } catch (Throwable ignored) {}
        }
    }
#else
    @Override
    public void render(GuiGraphics graphics, int mouseX, int mouseY, float partialTick) {
        if (parentScreen != null) {
            try {
                parentScreen.render(graphics, -999, -999, partialTick);
            } catch (Throwable ignored) {}
        }
    }
#endif

3.2 Render State Extraction & Transparency

In Minecraft 26.x, `Screen.render` was refactored by Mojang into `Screen.extractRenderState`. XMusic safely extracts parent screen state (`TitleScreen` or `PauseScreen`) inside try-catch guards. When opened in-game via hotkey (`parentScreen == null`), no opaque backdrop rectangle is drawn, keeping the live 3D world fully visible.

3.3 Registry & Component Binding Guards

During early Minecraft startup splash screen (`LoadingOverlay`), built-in Item `Holder.Reference` component maps are not yet bound (`areComponentsBound() == false`). Calling `bindComponents(EMPTY)` on item holders during this phase permanently corrupts native item components. XMusic guards item stack instantiations with `if (!holder.areComponentsBound()) return null;`, ensuring items render cleanly both in the main menu and in-game.

4.2 Developer Event API

Developers can hook into XMusic playback events using the PlayerFacade.getInstance() controller:

Java API Usage Example 
// Play a track programmatically
PlayerFacade facade = PlayerFacade.getInstance();
facade.playTrack(TrackRef.fromYouTube("dQw4w9WgXcQ", "Never Gonna Give You Up", "Rick Astley"));

// Listen for playback state changes
facade.addStateListener(state -> {
    System.out.println("Now playing: " + state.getCurrentTrack().getDisplayName());
});

4.3 Troubleshooting & Diagnostics

  • No Audio Output: Verify Minecraft's master volume slider and ensure OpenAL output device is selected in Windows/OS audio settings.
  • YouTube Stream Error: Check if local firewall blocks HTTPS connections to pipedapi.kavin.rocks or github.com/yt-dlp.
  • Log Location: Full debug logs are written to .minecraft/logs/debug.log under the [XMusic] prefix.
